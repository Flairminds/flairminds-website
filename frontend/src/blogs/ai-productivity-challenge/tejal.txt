AI Adoption in Day-to-Day DevOps Operations 
 
1. AI for Troubleshooting & Root Cause Analysis 

I use AI tools such as GitHub Copilot to analyze error logs, CI/CD pipeline failures, and Kubernetes issues. 
Instead of searching multiple documents, AI quickly explains: 

Reasons for Jenkins pipeline failures 

Common causes of Kubernetes CrashLoopBackOff 

Terraform and AWS error messages in simple terms 

Impact: Faster issue resolution, reduced downtime, and less dependency on senior engineers. 

2. AI for Infrastructure as Code (IaC) & Automation 

AI (cursor & windsurf) helps me to: 

Write and optimize Terraform scripts 

Create Dockerfiles and Kubernetes YAML manifests 

Generate Bash scripts for automation 

Understand and improve existing code written by others 

Impact: Saves development time, reduces syntax errors, and improves code quality. 

3. AI for Documentation & Knowledge Sharing 

I use AI (Notion Aito, ChatGPT, Microsoft Copilot): 

Convert technical work into clear documentation 

Create SOPs, runbooks, and handover notes 

Summarize long architecture and requirement discussions 

Impact: High-quality documentation with less effort and better team understanding. 

 
 
 
 
 
 
 

Innovative AI-Integrated Idea 

AI-Driven Deployment Readiness & Change Impact Assistant 

Problem Statement 

Production issues often occur due to: 

Missing environment variables 

Incorrect configuration changes 

Unreviewed infrastructure updates 

Poor understanding of deployment impact 

Manual reviews of PRs and Terraform plans are time-consuming and error-prone. 

Proposed Solution 

An AI Deployment Readiness Assistant integrated with: 

GitHub / GitLab Pull Requests 

CI/CD pipelines (Jenkins, GitHub Actions) 

Terraform plan outputs 

AI automatically reviews changes before deployment and provides readiness feedback. 

 

How It Works 

PR Analysis: 
Scans code changes, Dockerfiles, Kubernetes YAML, and Terraform configs; detects breaking changes, missing variables, and security risks. 

Infrastructure Impact Summary: 
Converts Terraform plans into plain-English summaries, e.g., 

“This change deletes 1 EC2 and creates 2 subnets” 

“RDS will be publicly accessible” 
Each change is tagged with a risk level: Low / Medium / High. 

Deployment Readiness Score: 
Generates a score based on tests, infra changes, and past failures. 
Example: Deployment Readiness: 85% – Medium Risk 
Recommendation: Review security group changes before approval.
