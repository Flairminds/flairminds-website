Engineering Decisions

Four Choices That Define the Platform

On-premise LLM is not a compromise — it is a feature.
Llama 3.1 via Ollama: no external rate limits, predictable latency, audit quality indistinguishable from frontier APIs for this constrained task. Temperature 0.2 ensures regulatory consistency.
The Safe-Path policy eliminates a category of false negatives.
Weighted averages allowed CRITICAL TBML flags to be diluted by LOW ML scores. Maximum-severity override eliminates this failure mode entirely — asymmetric consequences demand asymmetric policy.
Fuzzy matching threshold is a business decision, not a technical one.
The 80% Levenshtein threshold was set in consultation with compliance requirements — not optimised for F1 score alone. Too low floods queues. Too high lets phonetic variants of sanctioned names through.
Immutability at the database policy level, not the application layer.
Supabase row-level security enforces INSERT-only — a direct SQL DELETE returns a 403 even for administrators. This is the guarantee regulators need and lawyers can defend in court.

Conclusion

No External Data. No Vendor Lock-In. No Black Box.

SwiftIQ demonstrates that enterprise-grade AML compliance doesn't require expensive vendor platforms or external data sharing. An open-source stack — React, Flask, XGBoost, Isolation Forest, Supabase, and Llama 3.1 on Ollama — delivers screening quality, audit trail depth, and regulatory defensibility at the level of production financial institution deployment.

The four-tier decision chain with Safe-Path consensus is the core insight: combining deterministic rules, probabilistic ML, fuzzy entity matching, and AI narrative synthesis with a maximum-severity override achieves both high recall on true positives and a professionally auditable record of every decision — while running entirely within the institution's own network.
